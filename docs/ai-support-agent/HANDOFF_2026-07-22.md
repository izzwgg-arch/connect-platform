## 2. Deploy workflow (learned + used all session)

Builds on loopcom are **slow** (Docker layer export 3–4 min; the Next.js portal
build + typecheck runs ~15–20 min under load). Iterate like this:

1. Edit the file locally (in the mounted repo).
2. Ship to the server working tree:
   `base64 "$PROJ/<path>" | ssh … 'base64 -d > /opt/connectcomms/app/<path>'`
   (Paths containing `(platform)` break an unquoted remote shell — stage to
   `/tmp/x` then `cp` into place.)
3. **Fast path (agent only):** `docker cp <file> app-agent-1:/app/<path>` then
   `docker restart app-agent-1`. The container keeps its writable layer across
   `restart`, and `tsx` re-reads source on boot, so the change is live in ~10s.
4. **Durability:** also run `docker compose … build agent` (and recreate later)
   so the change is baked into the image and survives a full recreate.
5. **Portal** must be rebuilt (`docker compose -f docker-compose.app.yml build
   portal`) then `up -d --no-build --force-recreate --no-deps portal`. No
   hot-patch shortcut for Next.js.

Poll builds with: `ps -eo cmd | grep -E "compose.*build <svc>" | grep -v grep`.

## 4. Architecture decisions (the "why", so nobody re-litigates them)

- **Yiddish Labs does ALL translation, both ways (YI↔EN). Claude works in
  English only** and must never translate. YL is "king" because it is built for
  **American Yiddish** = Yiddish that naturally carries many English words
  ("order", "please", "ETA", "processed"). That is *not* code-switching to
  English; it is how the language is spoken, and YL handles it correctly.
- **Voicemail language routing is Yiddish-biased on purpose.** The community is
  Yiddish-first and the reported bug was Yiddish-shown-as-English, so the only
  acceptable residual error is a short *English* call leaning Yiddish (the safe
  direction). GPT‑4o cannot reliably read Yiddish, so the judge leans on English
  coherence + a strong Yiddish default.
- **ivrit.ai transcribes as fallback; Yiddish Labs transcribes as primary** for
  voicemail. ivrit = RunPod serverless endpoint `536xyqv8oyqygx`, model
  `ivrit-ai/yi-whisper-large-v3-turbo-ct2` (env `EVERETT_MODEL`). A warm endpoint
  (RunPod FlashBoot + idle timeout, then `AGENT_IVRIT_KEEPWARM=1`) is still TODO.
- **Compliance:** Yiddish Labs is used for **transcription + translation ONLY,
  never training** (`TRAINING_FORBIDDEN_MODELS`, enforced at capture/approve/
  export; `complianceReport().yiddishLabsTrainingEligible` must stay 0). Keep the
  evidence trail — see `YL_NO_TRAINING_POLICY.md`.
- **Widget mic split:** Yiddish must be **record-then-transcribe** (YL live is
  too slow); English can be **live** (fast, browser-side). Hence the YI/EN toggle.

## 5. Secrets & keys (IMPORTANT gotcha)

Provider keys resolve **secret store first, env fallback**. The **env vars are
stale/invalid** — the valid keys live encrypted in the `AgentSecret` table:
`anthropic_api_key`, `openai_api_key`, `yiddishlabs_api_key`, `ivrit_api_key`.
The agent decrypts them with `CREDENTIALS_MASTER_KEY` via `@connect/security`.
- `env YIDDISHLABS_API_KEY` returns **401 invalid** — do not test with it. Use
  `providerKeys.yiddishLabsApiKey` (which pulls the secret) inside the agent.
- Diagnostic tip: to test transcription outside a browser you need **real
  encoded audio** (webm/wav with headers). The raw voicemail stream
  (`/voice/voicemail/:id/stream?raw=1`) is headerless PCM and both YL and OpenAI
  reject it with 400 ("Could not detect audio duration" / "model does not
  support the format"). Not a bug — use browser MediaRecorder output.
