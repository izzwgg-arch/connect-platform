- ✅ **Architecture recommendation:** retain the existing Loopcom Assistant as the only orchestration/tool/context authority; put an audio/video session adapter beside it, use the existing self-hosted LiveKit room for media, and attach an avatar provider as the visual video-track publisher. This is a presentation layer, not a second LLM, knowledge base, support memory, customer-context service, tool registry, or technical-support product.
- ✅ **Provider recommendation for a pilot:** Anam over the existing LiveKit transport. LiveKit documents avatar plugins as a separate participant which publishes synchronized audio/video into the same room; Anam has both Python/Node LiveKit support and published custom-avatar, API, concurrency and overage details. Do not choose it or create an account until avatar direction and policy choices are approved.
- ⚠️ The existing self-hosted LiveKit has a known relay/hairpin limitation and Europe-host media path noted in `AGENT_HANDOFF_VIDEO_MEETINGS_2026-08-20.md`; a human two-machine acceptance test and a video-support transport readiness assessment are required before any production commitment.
