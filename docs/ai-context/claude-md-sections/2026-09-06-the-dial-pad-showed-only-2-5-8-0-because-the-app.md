Izzy, 2026-09-06, screenshot from Secro Selutions ext 301 "Gitty" (Galaxy S24+): *"Why does this keep happening?"* — then *"why is it only one user and only occasionally?"*

- ⛔⛔ **THE CAUSE: `KeypadTab.tsx` read `Dimensions.get('window').width` ONCE at module load and turned it into the key width (`KEY_CELL_WIDTH`).** Key HEIGHT was recomputed live from `onLayout`, which is why the rows looked right while the columns were wrong: keys sized for a 915 dp row, three per row centred as a group, so 1/3, 4/6, 7/9 and */# sat off both edges and only the middle column showed. The activity is locked portrait — but **the JS bundle usually loads with NO activity** (a ring/wake push or the keep-alive service creates the process headless), so there is no portrait lock at that instant; a phone lying sideways with auto-rotate on reports the LANDSCAPE width, and `SipKeepAliveService` keeps that process alive for days. **Only one user, only occasionally = a process RESTART coinciding with the phone being physically sideways.** Rotating the phone changes nothing; force-stop was the only cure.
- ✅ **THE FIX: `apps/mobile/src/ui/usePhoneLayoutWidth.ts`** (`useWindowDimensions()` clamped to the SHORT side by the pure `phoneLayoutWidth()` in `ui/phoneLayoutWidth.ts`, so even a rotated/headless reading yields the portrait width; 240–520 dp sanity clamp). Five screens converted: `KeypadTab` (key + grid + delete-button offset), `ActiveCallScreen` (caller-name maxWidth, DTMF keys), `CallsDrawer` (dropdown), `ChatTab` (image grid / video / voice bubble — the styles lost their width and it is set inline per render), `IncomingCallScreen` (the read was DEAD CODE — deleted). ⛔ **Never derive a layout width from `Dimensions.get()` at module scope in `apps/mobile` again.**
- ✅ **Proven:** `pnpm --filter @connect/mobile test:window-width` — 8 tests, pure maths on the real S24+ sizes (412×915 / 915×412) plus a **source guard over all five screens**; replayed with `MOBILE_GUARD_ROOT=<HEAD tree>` **2 of 8 fail against the pre-fix code**. Mobile `tsc` 0. ⛔ The test names its files explicitly in `package.json` (the documented unregistered-test trap) — it is registered.
