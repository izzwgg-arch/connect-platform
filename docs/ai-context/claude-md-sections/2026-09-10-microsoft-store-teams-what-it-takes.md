# ⛔ AGENT HANDOFF — Microsoft Store + Teams: what it takes (researched 2026-09-10, NOTHING filed) — READ FIRST before promising a Teams integration, before submitting the desktop app to the Microsoft Store, or before buying a code-signing certificate for it

(**Research only — no account, no code, no deploy.** Sources read live 2026-09-10: Microsoft Learn MSI/EXE package requirements, the company-onboarding page, the winapp Electron packaging guide, the Teams Store submission checklist. Memory: [[microsoft-store-and-teams-what-it-takes]]. - ✅ **The Microsoft Store company developer account is FREE since 2026-05-07** (the $99 fee is gone for NEW company accounts — only via `storedeveloper.microsoft.com`). Verification is automated when you give a **D-U-N-S** (Loopcom has **149921594**); documents go to manual review, 2–5 business days. ⛔ Needs a **work email on loopcom.net** (Gmail refused) and the exact legal name `Loopcom LLC`. Sign-in may be a personal MSA or an Entra work account; Entra onboards the whole tenant.
- ⛔⛔ **TWO ROUTES INTO THE STORE, AND THE ONE THAT FITS THE CURRENT INSTALLER NEEDS A CERTIFICATE WE DO NOT HAVE.** **(A) EXE/MSI route** = submit an HTTPS URL to our own NSIS installer (`/desktop/Connect-Setup-latest.exe` already qualifies: silent `/S`, standalone, per-user, no UI) — but *"the binary and all of its PE files must be digitally signed with a code signing certificate that chains up to a CA in the Microsoft Trusted Root Program"*, and **Microsoft does NOT re-sign it**. The desktop app is UNSIGNED today (the 2026-08-21 desktop-rebrand section records why: Azure Trusted Signing needs a 3-year-old business, an EV cert is ~$300–700/yr). Every version = a new versioned URL in Partner Center; updates stay ours (electron-updater keeps working). **(B) MSIX route** = electron-builder `appx` target (Windows SDK needed on the build box); **the Store signs it for free** and hosts it; ⛔ **electron-updater does not work inside AppX/MSIX** (Store handles updates), so the Store build is a SEPARATE build with the updater off. ⛔⛔ **An MSIX has a different package identity from the NSIS install, so a customer with both ends up with TWO Loopcom apps = two SIP registrations on one extension = a double ring** (the `DesktopWindowKind` / second-phone class). Never ship (B) to a machine that has the NSIS build without an uninstall step.
- ⛔ **Untested under MSIX and each could break:** the PowerShell `SendInput` helper + elevated named-pipe helper (remote support), the UDP 5060 PnP listener, `%LOCALAPPDATA%\Programs\@connectdesktop` paths, the tray, `installer.nsh`'s orphan-shortcut cleanup (NSIS-only). Full-trust MSIX usually allows all of it, but nobody has run the app that way.
- ⛔⛔ **WHAT IZZY ACTUALLY MEANT (corrected the same day): a customer signs in to their EXISTING Microsoft account inside Loopcom and works their Teams from the Loopcom app — NOT a Loopcom app inside Teams.** The sign-in is ordinary Entra ID OAuth ("Sign in with Microsoft"), free, from a multi-tenant app registration in our own Entra tenant. What Microsoft Graph then lets a third-party app do AS THAT USER: read + send 1:1/group **chats** (`Chat.ReadWrite`), channel posts (`ChannelMessage.Send`, read via `ChannelMessage.Read.All`), **presence** read/write (`Presence.ReadWrite` — Teams polls it, minutes of lag), **create/list meetings** (`OnlineMeetings.ReadWrite`), and directory/people. ⛔⛔ **MOST OF THAT NEEDS THE CUSTOMER'S TENANT ADMIN TO APPROVE LOOPCOM ONCE PER COMPANY:** since Oct/Nov 2025 (MC1163922) the Microsoft-managed default consent policy moved `Chat.Read`, `Chat.ReadWrite`, `ChannelMessage.Read.All`, `OnlineMeetings.Read/ReadWrite`, all `Mail.*` and `Calendars.*` (and from June 2026 `Contacts.ReadWrite`, `People.Read`, `Tasks.*`) to ADMIN consent — publisher verification does NOT exempt us. The platform-auth section's "only Mail/Calendars" list was incomplete. So the product shape is **an admin-consent link the customer's IT clicks once, then every user signs in**; a one-person shop where the owner IS the admin clicks it themselves. `Presence.*` and `User.Read` stay user-consentable.
- ⛔⛔ **A TEAMS CALL CANNOT BE PLACED OR ANSWERED FROM LOOPCOM.** Graph's calling API is application-only (a BOT is the participant, needs a calling-bot registration + tenant enablement), there is no delegated "call as this user", and Teams audio/video interop for third parties is closed (08-21 section). A Teams meeting shows in Loopcom as a join link that opens the Teams client/browser. Teams-as-the-phone is still Direct Routing = a certified SBC (anynode ~$53.90/mo per 10 sessions).
- ⛔ **Change notifications for chat (`/chats/{id}/messages`) work with delegated permission** — no "protected API" form for per-chat subscriptions; the tenant-wide `getAllMessages` app-only feed IS gated and is not needed for this shape.
- ⛔ **Create the Entra tenant ONCE and use it for everything Microsoft** — Teams app, Publisher Verification, the Store account, a future Outlook connect. An app object cannot be moved between tenants later.
