## 2. THE FACTS THAT MADE THIS BUILDABLE TODAY (all verified 2026-09-16)

⛔ These are the load-bearing discoveries. The Phase-0 plan assumed we would need a new provider account,
object storage and a GPU. **None of that was true.**

- **The OpenAI key already in `AgentSecret` can do images AND video.** `gpt-image-2.5-flare`,
  `gpt-image-2`, `gpt-image-1.x` and **`sora-2` / `sora-2-pro`** are all on the account. No new provider,
  no new spend commitment.
- ⛔⛔ **Sora's real limits, read from its own validation errors:** `seconds` ∈ **{4, 8, 12}** only, `size` ∈
  {720x1280, 1280x720, 1024x1792, 1792x1024}. **There is no 15.** That is why `planVideoSegments()` exists
  and why a 15-second ask is composed — do not "simplify" it away.
- **`connectcomms-minio` was already running on `infra_default`, completely unused** (no buckets). api and
  worker are both on that network and reach it (health 200). That is the object storage; R2 was not needed.
- **FFmpeg 5.1.9 is in the api and worker images**, so joining, trimming, thumbnails, captions and
  re-framing cost nothing per run.
- ⛔ The api/agent/worker containers hold a **placeholder** `OPENAI_API_KEY` (`"(paste y…key)"`). The real
  keys live encrypted in `AgentSecret` (AES-256-GCM, `CREDENTIALS_MASTER_KEY`) and are read through
  `resolveCreativeSecret()`, which copies `voice/elevenLabsKey.ts`. **Never "fix" the env placeholder.**

## 3. SHAPE

```
portal /creative/*  ─┐
                     ├─→ apps/api/src/creativeStudio/service.ts  ← ONE implementation
Coworker tools ──────┘        (safety → engine choice → quota → brand kit + memory → job)
                                  │
                     jobs.ts (the job ROW is the truth; claim + lease + heartbeat)
                                  │
              engines.ts (adapters) ── openai images / sora video / elevenlabs voice+music
              localJobs.ts (ours)   ── export, timeline render  → media.ts (FFmpeg)
                                  │
                     assets.ts → storage.ts → MinIO   +   CreativeAsset rows
```

- **`service.ts` is the only way to start a generation.** The browser and the agent both go through it, so
  asking the Coworker can never skip the safety check, the quota check or the brand kit. ⛔ Do not add a
  second path.
- **`runCreativeCycle()` runs inside the api** on a 5-second timer (`CREATIVE_CYCLE_INTERVAL_MS`),
  claiming at most 2 jobs. It is written as a worker loop so it can be moved to `apps/worker` unchanged
  when volume justifies it.
- **Job states:** queued → claimed → running → succeeded / failed / cancelled. A provider-side job keeps
  its `providerJobId` and is polled; a lease that expires is swept back to the queue **unless** it has a
  provider job, in which case it goes back to polling rather than being paid for twice.

## 4. THE RULES THAT ARE CODE, NOT COMMENTS

- ⛔ **Licence gate.** `CreativeEngine.commercialOk = false` → `chooseEngine()` will not return it and
  `PATCH /admin/creative/engines/:id {enabled:true}` answers **422**. That is the enforcement of the whole
  Phase-0 licence finding.
- ⛔ **Company from the session only.** Every read is `findFirst({ where: { id, tenantId } })` and answers
  **not found**, never forbidden. Storage keys begin `t/<tenantId>/`, so a cross-company read cannot even
  be expressed.
- ⛔ **Money asks first.** `checkQuota()` runs before any provider call. Cancelling records the part-done
  work as spent (`wasted: true`) rather than hiding it.
- ⛔ **Idempotency.** `tenantId + idempotencyKey` is unique; the same request twice returns the same job.
- ⛔ **FFmpeg** is `execFile` with an argument array and `-protocol_whitelist file,pipe` on **every** call —
  a crafted playlist would otherwise make our own server fetch URLs.
- ⛔ **Uploads** are sniffed from their bytes (`sniffMime`), not their filename, and only an allowlisted
  type is stored.
- ⛔ **No tool publishes anything.** Export produces a file; a person sends it. A test asserts no
  `creative_(post|publish|send|email|share)_*` tool exists.

## 5. TWO BUGS THE TESTS CAUGHT (both were real)

1. **A run of dots survived `safeSegment`**, so `../../etc/passwd` became `_.._.._etc_passwd` — a key still
   containing `..`. Harmless in S3, dangerous the day anybody joins a key onto a filesystem path. Fixed by
   collapsing dot runs.
2. **`cancelJob()` read `job.status` AFTER its own update.** With Prisma's detached rows it worked; with a
   client that returns the same object it silently skipped recording the spend. Now the state is captured
   before the write. ⛔ General lesson: never re-read a local variable across your own mutation.

## 6. THE MISTAKE I MADE, AND THE ONE ANOTHER SESSION CAUGHT

- ⛔⛔ **`/internal/agent/creative/*` answered `unauthorized` on the first production call.** The handler
  checks the shared secret, but **the JWT preHandler rejects the request before the handler runs**.
  `jwtPublicRouteBypass.ts` says so in its own comment — *"Any new /internal/agent/* door must be added
  here too"* — and I did not read it carefully enough. Fixed in `8a914d26`; a test now pins it.
- ⛔⛔ **A patch of mine anchored on `} from "lucide-react";`, which ALSO matches inside
  `import type { LucideIcon } from "lucide-react";` on line 1 of navConfig.** The rebuild merged the two
  imports and nothing in the portal typechecked from origin. **Another session (connect-2-8f) caught it and
  repaired it in `88682602`.** A test now pins navConfig's import shape. General lesson for this shared
  tree: when re-applying an edit onto origin, anchor on something that appears **once**.
